# sync-toc-context スキル

VketCloudSDK_Documentsリポジトリのドキュメントを要約し、AIエージェント向けリファレンスを自動生成するスキルです。

## 出力ファイル

| ファイル | 説明 |
|----------|------|
| `toc/context/summary.md` | 各ドキュメントの要約とリンク一覧 |
| `toc/context/history.md` | 実行履歴（最新が上） |

## 処理フロー

以下の順序で処理を実行してください。

### ステップ1: 前回記録の読み込み

1. `toc/context/history.md` を読み込む（存在しない場合は初回実行として扱う）
2. 前回の同期日時、処理ファイル数を取得

### ステップ2: 目次ファイルの読み込み

1. `toc/file-url.md` を読み込む
2. マークダウンリンク形式 `[タイトル](パス)` を解析
3. 各ドキュメントのタイトルとパスを抽出
4. カテゴリ（セクション）ごとにグループ化
5. **重複チェック**: 同じパスが複数回出現する場合は1回のみカウント（ユニークなファイル数を記録）

**重複の例:**
- `Vket Cloud Settings` セクションと `VKCコンポーネント > VKC Setting` セクションで同じファイルが参照される場合がある
- 重複は要約生成時に除外し、最初に出現した箇所でのみ要約を記載する

### ステップ3: ドキュメント要約の生成

**重要: コンテキスト削減のため、`Task` ツールを使用してカテゴリごとにサブエージェントで処理する**

#### カテゴリ分割ガイドライン

| 項目数 | サブエージェント数 |
|--------|-------------------|
| 1〜15 | 1エージェント |
| 16〜30 | 2エージェント |
| 31〜45 | 3エージェント |
| 46以上 | 4エージェント |

**分割の基準:**
- `toc/file-url.md` のカテゴリ構造に従う
- サブカテゴリがある場合はサブカテゴリ単位で分割を検討
- 論理的なまとまり（例: VKC Setting/Item/Node）で分割

#### サブエージェント起動方法

`Task` ツールで `subagent_type: "general-purpose"` を使用し、以下のプロンプトテンプレートでサブエージェントを起動:

```
以下のドキュメントを読み込み、各ページの要約を生成してください。

## 対象ファイル
[カテゴリ内のファイルパスリスト]

## 出力形式
マークダウンテーブル形式で出力:

| ページ | 要約 | 参照シーン |
|--------|------|------------|
| [タイトル](パス) | 1-2行の要約 | 機能追加/不具合修正/リファクタ等 |

## 要約のガイドライン
- 各ファイルの冒頭50行程度を読み込む（limit: 50）
- このページで説明している機能/概念を簡潔に記述
- 参照シーンは以下から選択（複数可）:
  - 初期セットアップ
  - 機能追加
  - 不具合修正
  - リファクタ
  - パフォーマンス改善
  - デバッグ
```

#### 並列実行

独立したカテゴリのサブエージェントは並列で起動可能:

```
# 例: 同時に複数のTaskツールを呼び出す
Task(VKCコンポーネント - Setting系)
Task(VKCコンポーネント - Item系)
Task(VKCコンポーネント - Node+Attribute系)
Task(HeliScript - 概要・型)
Task(HeliScript - クラス)
...
```

### ステップ4: 要約ファイル生成

全サブエージェントの結果を統合し、`toc/context/summary.md` を生成:

```markdown
# VketCloudSDK ドキュメント要約

> 最終更新: YYYY-MM-DD HH:MM:SS
> 処理ファイル数: XXX

## 使い方

このドキュメントは、VketCloudSDKプロジェクトの機能追加・不具合修正・リファクタを行う際の参考資料です。
「参照シーン」列を確認し、現在の作業に関連するドキュメントを参照してください。

---

## カテゴリ名

| ページ | 要約 | 参照シーン |
|--------|------|------------|
| [ページタイトル](docs/path/to/file.ja.md) | このページで説明している内容の要約 | 機能追加, 不具合修正 |
| [別のページ](docs/path/to/another.ja.md) | 別のページの要約 | リファクタ |

## 別のカテゴリ名

| ページ | 要約 | 参照シーン |
|--------|------|------------|
| ... | ... | ... |

（toc/file-url.md のカテゴリ構造に従って生成）
```

**注意:**
- カテゴリ構造は `toc/file-url.md` に従う
- サブカテゴリがある場合は `###` で階層化
- 項目の増減に応じて柔軟に対応

### ステップ5: 項目数検証

生成した `summary.md` の項目数が `file-url.md` と一致するか検証する。

#### 検証コマンド

```bash
# file-url.md のユニークなリンク数をカウント
grep -oE '\[.*\]\(docs/.*\.ja\.md\)' toc/file-url.md | sort -u | wc -l

# summary.md のリンク数をカウント
grep -c '\[.*\](docs/.*\.ja\.md)' toc/context/summary.md
```

#### 検証結果の解釈

| 状態 | 説明 | 対応 |
|------|------|------|
| 一致 | ユニーク項目数が同じ | 正常完了 |
| summary.md が少ない | サブエージェントが一部ファイルを処理していない | 不足ファイルを特定し、追加で要約を生成 |
| summary.md が多い | 重複エントリが存在 | 重複を削除 |

#### 不一致時の対応

1. `file-url.md` のユニークなパス一覧を抽出
2. `summary.md` に含まれるパス一覧を抽出
3. 差分を特定（`comm` や `diff` コマンドを使用）
4. 不足ファイルがあれば追加で要約を生成
5. 重複があれば削除

```bash
# 差分確認の例
grep -oE 'docs/[^)]+\.ja\.md' toc/file-url.md | sort -u > /tmp/file-url-paths.txt
grep -oE 'docs/[^)]+\.ja\.md' toc/context/summary.md | sort -u > /tmp/summary-paths.txt
comm -23 /tmp/file-url-paths.txt /tmp/summary-paths.txt  # file-url.mdにのみ存在
comm -13 /tmp/file-url-paths.txt /tmp/summary-paths.txt  # summary.mdにのみ存在
```

### ステップ6: 履歴記録

`toc/context/history.md` に実行記録を追加（最新が上）:

```markdown
# sync-toc-context 実行履歴

## YYYY-MM-DD HH:MM:SS
- **処理ファイル数**: XXX（ユニーク）
- **カテゴリ数**: XX
- **サブエージェント数**: XX
- **検証結果**: OK / NG（不一致の場合は詳細を記載）
- **差分**: +Xファイル, -Xファイル（前回比）
- **更新ファイル**: summary.md

[既存の履歴...]
```

**履歴の追加方法:**
1. 既存の `toc/context/history.md` を読み込む（存在しない場合は新規作成）
2. ヘッダー（`# sync-toc-context 実行履歴`）の直後に新しいエントリを挿入
3. 既存のエントリはそのまま保持

### ステップ7: 完了報告

処理完了後、以下の形式で報告:

```
## sync-toc-context 完了

### 生成ファイル
- toc/context/summary.md
- toc/context/history.md

### 統計
- 処理ファイル数: XXX（ユニーク）
- カテゴリ数: XX
- サブエージェント使用数: XX

### 検証結果
- file-url.md ユニーク項目数: XXX
- summary.md 項目数: XXX
- 結果: OK / NG

### 差分（前回比）
- 新規: +X ファイル
- 削除: -X ファイル
```
