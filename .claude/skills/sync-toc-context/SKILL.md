# sync-toc-context スキル

VketCloudSDK_Documentsリポジトリのドキュメントを要約し、AIエージェント向けリファレンスを自動生成するスキルです。

## 前提条件

- `sync-toc` スキルで `toc/file-url.md` が生成済みであること
- `toc/file-url.md` が存在しない場合は、先に `sync-toc` スキルを実行するようユーザーに案内する

## 出力ファイル

| ファイル | 説明 |
|----------|------|
| `toc/context/summary.md` | 各ドキュメントの要約とリンク一覧 |
| `toc/context/history.md` | 実行履歴（最新が上） |

## 対象ファイル

- **対象**: `.ja.md` ファイルのみ
- **対象外**: `.en.md` ファイル（英語版は日本語版と内容が同じため除外）

## 除外セクション

`sync-toc` スキルで除外されたセクションは、本スキルでも要約対象外とする:

- リリースノート (Release Note)
- チェンジログ (Changelog)
- タグ規約 (Tag Conventions)
- 利用規約 (Terms of Use / License)
- トラブルシューティング (Troubleshooting)
- FAQ

※ これらのセクションは `toc/file-url.md` に含まれていないため、自動的に除外される。

## 処理フロー

以下の順序で処理を実行してください。

### ステップ0: 前提条件の確認

1. `toc/file-url.md` の存在を確認
2. 存在しない場合はエラーメッセージを表示して終了

### ステップ1: 出力ディレクトリの準備

1. `toc/context/` ディレクトリの存在を確認
2. 存在しない場合は作成

### ステップ2: 前回記録の読み込み

1. `toc/context/history.md` を読み込む（存在しない場合は初回実行として扱う）
2. 前回の同期日時、処理ファイル数を取得

### ステップ3: 目次ファイルの読み込み

1. `toc/file-url.md` を読み込む
2. マークダウンリンク形式 `[タイトル](パス)` を解析
3. 各ドキュメントのタイトルとパスを抽出
4. カテゴリ（セクション）ごとにグループ化
5. **重複チェック**: 同じパスが複数回出現する場合は1回のみカウント

### ステップ4: ドキュメント要約の生成

**重要: コンテキスト削減のため、`Task` ツールを使用してカテゴリごとにサブエージェントで処理する**

#### カテゴリ分割ガイドライン

| 項目数 | サブエージェント数 |
|--------|-------------------|
| 1〜15 | 1エージェント |
| 16〜30 | 2エージェント |
| 31〜45 | 3エージェント |
| 46以上 | 4エージェント |

**分割の基準:**
- `toc/file-url.md` のカテゴリ構造に従う
- サブカテゴリがある場合はサブカテゴリ単位で分割を検討
- 論理的なまとまり（例: VKC Setting/Item/Node）で分割

サブエージェント起動時のプロンプトテンプレートは `examples.md` を参照。

#### サブエージェントのエラーハンドリング

| エラー種別 | 対応 |
|------------|------|
| ファイルが見つからない | 警告をログに記録し、該当ファイルをスキップして継続 |
| タイムアウト | 該当カテゴリを再試行（最大2回）。失敗した場合は警告を記録して継続 |
| その他のエラー | 警告を記録し、該当ファイルをスキップして継続 |

エラーが発生したファイルは、最終報告の「警告」セクションにリストアップする。

#### 並列実行

独立したカテゴリのサブエージェントは並列で起動可能。

### ステップ5: サブエージェント結果の統合

1. 全サブエージェントの結果を収集
2. `toc/file-url.md` のカテゴリ順序に従って結果を並べ替え
3. テーブルヘッダーの重複を除去（各カテゴリで1つのみ）
4. フォーマットの統一:
   - パスの形式: `docs/path/to/file.ja.md`
   - 要約: 句点（。）で終わる
   - 参照シーン: カンマ区切り

**統合時の注意:**
- 重複エントリ（同じパスが複数回出現）は最初の1件のみ残す
- 空の要約がある場合は「（要約なし）」と記載

### ステップ6: 要約ファイル生成

全サブエージェントの結果を統合し、`toc/context/summary.md` を生成。

※出力形式の詳細は `examples.md` を参照

### ステップ7: 項目数検証

生成した `summary.md` の項目数が `file-url.md` と一致するか検証する。

| 状態 | 説明 | 対応 |
|------|------|------|
| 一致 | ユニーク項目数が同じ | 正常完了 |
| summary.md が少ない | サブエージェントが一部ファイルを処理していない | 不足ファイルを特定し、追加で要約を生成 |
| summary.md が多い | 重複エントリが存在 | 重複を削除 |

※検証コマンドの詳細は `examples.md` を参照

### ステップ8: 履歴記録

`toc/context/history.md` に実行記録を追加（最新が上）。

**履歴の追加方法:**
1. 既存の `toc/context/history.md` を読み込む（存在しない場合は新規作成）
2. ヘッダー（`# sync-toc-context 実行履歴`）の直後に新しいエントリを挿入
3. 既存のエントリはそのまま保持

※出力形式の詳細は `examples.md` を参照

### ステップ9: 完了報告

処理完了時またはエラー発生時は、所定の形式で報告する。

※報告形式の詳細は `examples.md` を参照
